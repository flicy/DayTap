# 对外口径一页纸｜DayTap · 腕上日录 / 按需录音 → Agent

**产品名**：**DayTap**
**更新**：2026-11-04（Asia/Shanghai）  
**用途**：周五分享、公众号、Git README、群聊回复同一口径  
**结论先行**：腕上麦克风是 **DayTap Watch App**（前台按需，不是全天）。音频到 iPhone 后走 Track 1（不进得到）或 Track 2（只在手机上进得到），再进语料库和 Grok Bot。表没装好用手机 Track 0。不是 App Store 产品，也不包装成全天录音硬件。

---

## 1. 我们做什么

- 腕上用 **DayTap Watch App** 按需开录；文件到 iPhone 再转写。长课或还没装上时，手机 Track 0 保底。  
- **按需录音**（不是默认全天录）。  
- **按天**同步与整理。  
- 转录交给**得到**。  
- 沉淀为**文档语料库**。  
- 接入 **Grok Bot**：从语料生成**决策表 / PPT 草稿**。  
- **不同角色可切换 bot**（产品方向）。  
- 对外：周五分享 + 公众号 + **Git 开源方案**；其后 Reddit / 小红书（计划）。

一句话：录音是入口，Agent 指挥与沉淀才是目标。

## 2. 我们不做什么

- 不宣称「已把 Apple Watch 变成最好的 AI 录音硬件」（那是 Puppet 文的叙事，我们对标、不冒用）。  
- 不承诺本周五 **Watch 上实时指挥 Bot** 已跑通。  
- 不承诺 **实时**自动上传 → 当场 PPT 已稳定（云飞扬场景 = 目标，现状待验证）。  
- 不做默认**全天候、无感偷录**。  
- 不把群友聊天记录或用户录音**当商品对外售卖**。  
- 不在未验证时，用营收数字或「七天从零到卖出」话术包装自己。  
- 开源**不含**密钥、账号、未授权的个人音频。

## 3. 隐私边界

| 规则 | 口径 |
|------|------|
| 知情同意 | 对人录音前，场景需可解释；按需开录，可停。 |
| 最小必要 | 只保留进语料库所需片段；backup 不是第二套监控。 |
| 本地 / 云 | 手机主存；上云与第三方（得到、Grok）前要可关可删——**具体开关待验证**。 |
| 分享演示 | Demo 用可公开或已授权材料；群聊截图打码。 |
| 开源 | 开流水线、目录约定、skill 模板；不开用户语料。 |
| 撤回 | 用户要求删除某日录音/转录时，流程上要能删——**删除 SOP 待验证**。 |

对外回复模板：  
「我们按需录、按天整理；进 Bot 前你看得见清单。Watch 只是 backup，不是偷偷多录一路。」

### 待验证（禁止说成已完成）

- 手机主录 + Watch backup **端到端稳定**。  
- **按天同步**自动化与命名约定落地。  
- **得到**转录接入、准确率、成本。  
- 语料库结构（目录、元数据、检索）可用。  
- Grok Bot 从语料出**决策表 / PPT**（非实时可先通；**实时**另标）。  
- Watch 侧 **指挥** Bot（语音 API / 按钮 / 通知回传）。  
- **多 bot 切换**机制。  
- Git 仓库创建与首版 README。  
- 公众号成稿发布、Reddit/小红书效果。  
- 隐私开关与**删除 SOP**。  
- 任何收费 / 「完整数据反推供给侧」商业闭环（Jack 观点，非我方已验证模型）。
